## The decision

**SwiftUI + WKWebView shell in `apple/`**, not Capacitor and not a native rebuild.

- *Capacitor* would drag `node_modules` and CocoaPods into a repo whose whole convention is
  "no build, no dependencies", and its generated `ios/App` churns on every upgrade.
- *A native rebuild* would re-implement the verdict engine — the actual moat — in a second
  language and guarantee drift.
- The shell keeps **one copy of the domain logic**: the web app in the repo root is the source
  of truth, and a build phase copies it into the `.app`.

Directory is `apple/`, not `ios/`, to mirror Distavo — the pipeline being reused — and to
leave room for an iPad/Catalyst target without a rename.

### Three decisions worth remembering

**Custom URL scheme, not `file://`.** WKWebView gives `file://` pages an opaque security
origin, where `localStorage` is unreliable — and `localStorage` is where every water test
lives. `tankmate://app/` has a real, stable origin (the same reason Capacitor serves from
`capacitor://localhost`). **Changing the scheme or host orphans every user's data.**

**The Lemon Squeezy checkout is stripped at build time**, not hidden with CSS —
Guideline 3.1.1 forbids steering to an outside payment flow. `prepare-web-bundle.py` removes
it and **fails the build** if any trace survives. A side effect: the app then loads nothing
from the network, which is what makes offline structural rather than a cache.

**Local notifications are the point, not decoration.** Guideline 4.2 rejects bare webview
wrappers. Scheduled reminders are something iOS Safari cannot give a web app.
